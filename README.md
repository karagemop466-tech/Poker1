# Las Vegas Strip Poker Plan

A decision dashboard for single-entry poker tournaments on the Las Vegas Strip and walkable hotels.
Field-by-field dataset verification date: **2026-11-17**; this is not a claim that every source was freshly re-read then or since. The scheduled monitor last ran **2026-11-19 16:45 UTC**: 99 of 109 official sources answered, and four source fact signatures changed, marking four rows for re-check. A monitor fetch is not a manual re-verification; changed rows remain flagged until their values are checked against the official page. See [Monitoring](pages/monitoring.html), [Flagged for Review](pages/flagged.html), `REVIEW.md` §9 and `research/verification-2026-11-17.md`.

Live site: https://karagemop466-tech.github.io/Poker1/

## What is in the site

- `index.html`: landing page with counts and links.
- `pages/`:
  - `single-entry.html` - every event whose structure sheet confirms one entry only.
  - `separate-section.html` - possible multiple entries and re-entry events, kept out of the ranking.
  - `unverified.html` - official rows whose entry rule is not published in a structure sheet.
  - `daily.html` - morning official schedule excerpts plus the recurring Wynn daily formats, with fee splits and registration cut-offs.
  - `schedule.html` - day-by-day plan with one primary event per date, a conditional fallback only where
    the primary's own table cannot run past the second event's entry deadline, the alternatives that can
    replace the primary (never add to it), and every overlap the published ceilings actually support.
    Finish times are compared in absolute minutes, not clock strings, and a finish crossing midnight is
    labelled "the next day"; `scripts/check_links.py` fails the build if either rule is broken.
  - `payouts.html` - every row's payout rule quoted line by line from the archived official
    structure documents, with the snapshot lines behind each quote. A document that prints no
    payout rule says so explicitly (composition only, sheet prints no rule, placeholder sheet,
    not mapped, no sheet, source not captured); nothing is inferred. `scripts/check_links.py`
    re-derives every quote from its recorded snapshot lines on each build and fails on a mismatch.
  - `hotels.html` - resort fees, room-rate status, walking records and the dated rate log.
  - `calculator.html` - trip cost = entries x buy-in + nights x true hotel cost + parking + other, from
    dated official-engine quotes, with what the chosen stay window holds.
  - `venues.html` and `venue-*.html` - one page per poker room with its hotels and events.
  - `search.html` - one search box across every row, hotel, venue, rate entry and document.
  - Every tournament table's filter bar carries a **date selector** - presets (today, tomorrow, this
    weekend, next 7/30 days) plus a tick list of the dates the dataset actually holds - and the
    calculator prices the entry side from the day plan by default, one entry per night at that date's
    published primary's own buy-in, with a source link per line.
  - `requirements.html` - the requirement-by-requirement audit (`REQUIREMENTS.md`): each line of the
    brief marked done, partial or blocked, with the file that implements it, the page where it can be
    seen and the official source behind any value.
  - `monitoring.html` - source health, changed rows and every printed source flag.
  - `evidence-audit.html` - the independent check of the one value that decides the ranking: whether
    each event is really single entry. Every quoted span in the dataset is re-derived from the archived
    official document its row cites; every "no such clause appears anywhere" claim is re-tested; every
    daily-fee clause is attributed to the block that prints the quoted words; and the change monitor's
    own verdicts are checked for internal consistency. It reports what it caught and had fixed, not only
    what it currently catches.
  - `summary.html`, `questions.html`, `suggestions.html`, `flagged.html`, `review.html` - the
    decision-support documents.
- `data/*.json`: the dataset. Generated by `scripts/build_data.py`. Do not edit the JSON by hand.
- `assets/`: the shared stylesheet and client-side renderer. The site has no external CDN dependency.
- `research/`: the field-by-field verification log for every structure sheet that was read.
- `scripts/`: the generators, the validator, the source monitor and the headless page smoke test.
- `archive/prior-main/`: the earlier site and documents from other sessions, kept for reference. Not
  published.

## Rules used

- **Booking gate (November 19):** `SE` is reserved for affirmative whole-event one-entry, no-rebuy and no-add-on evidence. All 74 sheet-silent Venetian leads are `CAND`; none is a verified freezeout. The schedule is a conditional candidate comparison, not a bookable itinerary. **Across 59 archived official documents, not one prints a sentence that closes an event to a second entry** - `scripts/audit_entry_labels.py` re-checks that claim on every build and publishes the result on [the Evidence audit page](pages/evidence-audit.html).
- Possible multi-entry events are shown separately. The structure sheet clause only says a player who
  bags Day 2 chips may not play a subsequent flight.
- Milestone satellites are marked separately: their prize is a seat, not cash.
- Hotel true cost includes resort fees. A value is blank until it is verified from an official source.
  Nothing is inferred.
- Room rates are kept in a dated log: five quotes are on file, each with its stay dates, occupancy, room
  type, per-night rates, resort fee, tax total, cancellation terms, engine total and the date it was
  read. A true nightly cost is the engine's own checkout total divided by the nights - never a rate
  reconstructed from a percentage.
- Walking times are **routed**, not published: none of the properties publishes one. Each of the twelve
  hotel-to-poker-room rows records the OpenStreetMap foot-network time between geocoded coordinates,
  links the geocoding lookup and the routing query, quotes the official statement that fixes where the
  poker room is, and marks walks inside one resort as `internal` instead of timing them. The 30-minute
  rule is applied and the three hotels that fail it stay listed and flagged.
- **Spend advantage, per row.** `scripts/spend_advantage.py` derives, from the clause excerpt already stored on a row,
  whether the official document prices or permits a way to buy more chances: a priced later buy-in, re-entries sold
  during the event, another flight unless chips were bagged, no such clause printed, no sheet on file, or a
  continuation row. It is a reading of the document's own words, never an operator statement: it cannot promote a row
  to single entry, `scripts/check_links.py` re-derives all 317 records from the stored excerpts on every build, and a
  row whose sheet prices a further entry is refused the SE status.
- **Facts are compared like-for-like.** The monitor's published-facts signature is the union of a PDF's reading-order
  and layout renders - a merged table cell is the one thing the reading-order render cannot see - and each baseline
  entry records the extractor that produced it, so a change of algorithm is never reported as a change of value.
- Every table row links to an official source, and every rule field keeps the clause text it came from.

## Rebuild and check

```
python3 scripts/build_data.py        # regenerate data/*.json and data/row_snapshot.json
python3 scripts/build_site.py        # regenerate index.html and pages/*.html
python3 scripts/check_links.py       # data schema, official hosts, rule objects, schedule, hotel rates, page links
python3 scripts/audit_entry_labels.py # re-derive every entry label from the sentence its document prints
python3 scripts/monitor_sources.py   # check every official URL, report changed rows
node scripts/smoke_test.js           # render every page in a headless DOM (needs jsdom)
node scripts/check_date_filter.js    # date presets and the per-date tick list narrow the table
node scripts/check_calculator.js     # plan-priced entry total recomputed from the published rows
python3 research/requirements-audit-dd06081b/compare_wss_live_20261119.py  # 38/38 Wynn rows vs live capture
```

The Pages workflow (`.github/workflows/pages.yml`) rebuilds the data and the pages on every pull
request, fails on any diff, runs the schema and link checks, checks every official source, and
renders every page in a headless DOM before deploying `index.html`, `pages/`, `assets/`, `data/` and
the Markdown content files to GitHub Pages after a push to `main`.

`scripts/check_links.py` validates that the Markdown files are present, that every data row carries an
HTTPS source on an approved official host, that identifiers and derived fields are consistent, that every
rule field keeps its excerpt, source and retrieval date, that the day schedule matches the rows, that the
dated rate log is internally consistent, and that the generated pages have no broken link or fragment.
Automated checks do not replace reading the official source documents.

The monitoring workflow (`.github/workflows/monitor.yml`) runs daily, checks every official URL,
records the result in `data/monitoring.json`, compares every row with `data/row_snapshot.json` and
posts the result as an issue so a reviewer can re-read any structure sheet that moved.
