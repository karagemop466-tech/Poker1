# Las Vegas Strip Poker Plan

A source-verified plan for single-entry poker tournaments on the Las Vegas Strip and walkable hotels. Snapshot date: **2026-11-16**.

Live site: https://karagemop466-tech.github.io/Poker1/

## What is in the site

- `index.html`: landing page with the headline counts and links.
- `pages/`: all tournaments, single entry, separate section (multi-entry), unverified rows, day plan, venues, hotels, trip cost, source monitor, executive summary, questions, suggestions, flagged for review, sources and review.
- `data/*.json`: tournament, hotel, rate-log, day-plan, change-log and source data. Generated by `scripts/build_data.py` and `scripts/collect_official.py`. Do not edit the JSON by hand.
- `assets/`: shared stylesheet and client-side renderer. The site has no external CDN dependencies.
- `research/`: research notes for each task.
- `archive/prior-main/`: the earlier site and documents from other sessions, kept for reference. Not published.

## Rules used

- Only events whose official structure sheet has been read and shows **no** re-entry, rebuy, add-on, multiple-entry or starting-flight clause are listed as single entry. The sheet's own clause 8 is decisive: a sheet that prints "any player who bags chips for Day 2 may not play a subsequent flight" is **not** single entry.
- Possible multi-entry events are shown in a separate section and are never mixed into the single-entry set.
- Every event row quotes the official wording that decided its classification, with a link to the PDF.
- Hotel true cost is (dated rate + mandatory resort fee) x (1 + room tax). It stays blank until a rate is attached to a stay date on an official page.
- Walking times are not published by any operator, so they are blank. The Venetian, The Palazzo, Wynn and Encore are confirmed same-building or same-resort stays.
- Guarantee / buy-in is a descriptive ratio of two printed numbers, never a forecast. Bounty events are labelled because their guarantee includes bounties.
- Nothing is inferred, averaged or filled from a third party.

## Automation

`scripts/collect_official.py` fetches every official URL, extracts facts from the official PDFs with `pdftotext`, hashes each document's visible text, and writes `data/official_facts.json` and `data/change_log.json`. The scheduled workflow `.github/workflows/monitor.yml` runs it daily, rebuilds the site, and commits the result. A document that cannot be fetched keeps its previous facts and is logged as unreachable; no value is ever replaced with a guess.

## Rebuild and check

```
python3 scripts/collect_official.py   # fetch + extract + hash official documents (needs poppler-utils)
python3 scripts/build_data.py         # regenerate data/*.json
python3 scripts/build_site.py         # regenerate index.html and pages/*.html
python3 scripts/check_links.py        # JSON, local links, generated pages, official source hosts
```

The Pages workflow (`.github/workflows/pages.yml`) runs the checks on each pull request and deploys `index.html`, `pages/`, `assets/`, `data/`, and the Markdown content files used by the Executive Summary, Questions, Suggestions, Flagged for Review, and Repo Review pages after a push to `main`. `scripts/check_links.py` verifies those Markdown files are present and that every data source uses an approved official operator domain.
