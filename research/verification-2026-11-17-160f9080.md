# Line-by-line verification of the published dataset — 2026-11-17 (session 160f9080)

This session (branch `arena/160f9080-poker1`) ran a full line-by-line re-verification of every
published row against the raw official documents archived under `data/snapshots/`. Because the
sandbox cannot reach the operator domains (`venetianlasvegas.com`, `wynnlasvegas.com`,
`cdn.wynnresorts.com`), the check compares each published value against the official text the
monitoring job already archived in-repo, rather than re-fetching the web. Nothing was inferred or
filled in: a value that could not be found in an official document was blanked or flagged.

This is a complementary pass to `research/verification-2026-11-17.md` (session `bb9a3717`), which
re-fetched the live pages. Both are kept; neither is dropped.

## Method

New script: `scripts/verify_rows.py`. For each tournament row, hotel row and the dated rate log it
runs three independent checks:

1. **Money** — `buy_in_usd`, `guarantee_usd` and `house_fee_usd` must appear as a dollar token
   in the official document text (the row's own source URL plus its series schedule page).
2. **Time** — the published `start` must appear as a time token in the official text.
3. **Entry rule** — the published `entry_status` must agree with the independently parsed sheet
   verdict (`data/structure_rules.json` for Venetian sheets) or the WPT registration wording
   (`data/wpt_rules.json`).

A check that fails is reported either as a **hard failure** (a published value that is not in the
official text) or a **review item** (a documented interpretation, not a data error). Hard failures
block the build; review items do not. The result is written to `data/row_verification.json` and the
script is now a step in the `pages.yml` validate job.

## Irregularities found and corrected

Two real data-quality problems were found by the verifier and corrected. Both are recorded in
`FLAGGED.md` (F53, F54) and on the Flagged for Review page, and both rows carry the flag in the
dataset so the row can never be separated from the reason it is unusual.

### F53 — LIPS house fee conflated the LIPS flat fee

The LIPS structure sheets (31, 32, 33) withhold **two separate** amounts from the buy-in: a house
fee (Rake + Staff) and a flat fee for Vegas Connected, INC, DBA Ladies International Poker Series
(LIPS). An earlier build stored the *combined* withholding as `house_fee_usd` (e.g. $90 = $80 house
+ $10 LIPS on the $600 sheets), which contradicted the sheet's own clause 06 wording.

- Sheet 31 / 33 ($600): `$80 ... house fees (Rake + Staff)` + `$10 ... flat fee for ... (LIPS)`.
- Sheet 32 ($800): `$90 ... house fees (Rake + Staff)` + `$20 ... flat fee for ... (LIPS)`.

**Corrected:** `house_fee_usd` now stores the pure house fee ($80 on the $600 sheets, $90 on the
$800 sheet) and the LIPS flat fee is stored separately in a new `lips_fee_usd` field ($10 / $20).
The prize pool is unchanged (buy-in less both withholdings). Affected rows: r094, r106, r112, r114,
r118.

### F54 — Wynn Signature Series main-event guarantees had no official source

The Wynn Signature Series schedule PDF prints a buy-in, starting chips and levels for the multi-day
Day 1x main events but **no guarantee**, and the structures PDF is a "COMING SOON" placeholder. An
earlier build published guarantee amounts ($150,000 / $250,000 / $100,000 / $300,000) that appear
on **no** official source.

**Corrected:** the unsourced guarantees are left blank (`guarantee_usd: null`) and each affected row
is flagged. The guarantees the schedule **does** print are kept: the NLH Turbo ($10,000) and the
Sunday NLH events ($30,000). Affected rows: the 17 multi-day Day 1x main events.

## What this verifier does not do

It does not re-fetch the live web. It checks the dataset against the official text archived at the
time of the last monitoring run. The scheduled jobs (`monitor.yml` daily, `source-facts.yml`
weekly) re-fetch the operator domains from GitHub Actions, where the network is open, and record
any change; the verifier is the offline cross-check that every published value traces to a source.
